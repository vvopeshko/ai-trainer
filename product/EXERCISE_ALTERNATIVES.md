# Аналоги упражнений: дизайн

Дата: **25 октября 2026**. Статус: **фазы 1–2 реализованы**, подбор по целевой мышце (§10); остаток фазы 3 — план.

Цель: у каждого упражнения программы есть аналоги («бицепс — на тренажёре, гантелями, на блоке; суть одна»). Переключение не ломает программу и не теряет прогресс по старым упражнениям.

## 1. Что есть сейчас

- `planJson.days[].exercises[].alternatives` — массив ID упражнений. Заполняет LLM при генерации/импорте (`generateProgram.js`, `importProgram.js`, промпт: «1–2 slug-а замен, необязательно»); `programEditor` ставит `[]`. `workoutController` обогащает ID до `{ exerciseId, nameRu, slug }`.
- На тренировке: чип «Аналоги · N» и шторка (`WorkoutPage` → `handleSwapAlternative` / `executeSwap`, `handleSwapUpcoming` для следующих). Замена — только в состоянии текущей тренировки, в программу не пишется.
- **Проблемы:** замена после сделанных подходов **удаляет** их; на экране программы аналоги не редактируются; у импортированной программы их нет вовсе (прод, «V-Build»: 0 из 34 упражнений).

## 2. Модель

**Слот** — позиция упражнения в дне программы со схемой (подходы × повторы, отдых). У слота основное упражнение (`exerciseId`) и аналоги (`alternatives`). Программа не меняется от выбора на сегодня; меняется только сделанный вариант. Формат `planJson` подходит, миграция не нужна.

## 3. Принятые решения

| Вопрос | Решение |
|---|---|
| Что ставить в следующую тренировку после замены | **Основной вариант.** Если один и тот же аналог выбран **две тренировки подряд** — предложить «Сделать основным?» (не автоматически) |
| Прогресс по вариантам | **Раздельно** — килограммы тренажёра, гантелей и блока несравнимы. Статус каждого варианта — в шторке аналогов; «Другие варианты» в шите прогресса — фаза 3 |
| Заполнить аналоги текущей программы | **Да**, разово до 3 на слот без аналогов (`POST /programs/active/fill-alternatives`, идемпотентно) |

## 4. Подбор аналогов

1. **Каталог (фаза 1).** Кандидаты: те же `primaryMuscles`, та же `category` (compound/isolation), другое `equipment`. Выше — варианты из истории пользователя, затем `difficulty` не выше основного. Эндпоинт `GET /exercises/:id/alternatives`.
2. **Вручную.** «Заменить на…» через поиск каталога → «Запомнить как аналог?».
3. **Тип движения (фаза 3).** Разметка 924 упражнений полем `movementPattern` (сгибание локтя, горизонтальный жим, вертикальная тяга…) одним прогоном LLM — точнее «суть одна», чем мышцы + оборудование.

## 5. Поведение

- **Шторка аналогов на тренировке:** у каждого варианта — оборудование, последний результат, статус прогресса. Выбор: «Только сегодня» (по умолчанию) / «Сделать основным».
- **Замена после сделанных подходов:** подходы **не удаляются** (это реальная работа); аналог начинается следующим в том же слоте.
- **Подсказка «Сделать основным»:** храним выбранный вариант слота в тренировке; если в двух последних тренировках по этому дню программы выбран один аналог — показываем предложение при старте слота.
- **Вес и цель подхода** для варианта — из его собственной истории (`batch-last-results` уже по `exerciseId`); схема повторов — слота.
- **Экран программы:** раздел «Аналоги» у упражнения — добавить (подсказки + поиск), убрать, сделать основным.
- **Чат-тренер:** инструмент «замени насовсем / добавь аналог».
- **Свёрнутые строки «Далее»:** видно, какой вариант стоит на сегодня.
- Недельный объём по мышцам считается по фактическим упражнениям — аналоги учитываются автоматически.

## 6. Фазы

1. Эндпоинт кандидатов; шторка с последним результатом, статусом и «сегодня / основной»; замена без удаления подходов; подсказка после двух одинаковых замен; разовое заполнение аналогов программы.
2. Аналоги на экране программы; инструмент чат-тренера.
3. `movementPattern` в каталоге; «Другие варианты» в шите прогресса.

## 8. Реализация фазы 1

- **Подбор** — [exerciseAlternatives.js](../server/src/services/exerciseAlternatives.js), `GET /exercises/:id/alternatives` (до 8). Пул: та же первая основная мышца и `category`. Ранжирование: сначала то, что пользователь делал (рабочие подходы), затем общие основы слов названия (грубая замена типа движения: «Сгибания…», «Разгибания ног…»), тот же набор мышц, оборудование зала (штанга, гантели, блок, тренажёр, EZ, гири, свой вес; ролик/медбол/«другое» — штраф), другое оборудование. Исключены растяжки/релиз/разминка (в каталоге они бывают compound/isolation), дубли по названию; в голове списка — не больше двух одного снаряда. Проверено на каталоге: блочное разгибание → канат, верхний блок, кикбэк, гантель из-за головы.
- **Уточнение подбора (после заполнения прода):** исключены МФР/самомассаж и упражнения «с партнёром»; стороны одностороннего упражнения («(левая)/(правая)») — один вариант; для **базовых** упражнений обязательна общая основа движения в названии (жим ↔ жим, тяга ↔ тяга), причём слова-снаряды («штангой», «гантелей», «блоке»…) движением не считаются — иначе жим гантелей сидя получал фейс-пул, а ягодичный мостик — присед со штангой. Цена правила: у подтягиваний пропали тяги верхнего блока (их можно выбрать вручную в фазе 2 или из истории).
- **Перезаполнение:** `fill-alternatives { replace: [{ dayIndex, exerciseId }] }` заменяет аналоги перечисленных слотов; автозаполненные слоты помечаются `alternativesAuto: true`, выбор пользователя (`/slot`) снимает метку.
- **Слот программы** — `POST /programs/active/slot { dayIndex, mainExerciseId, exerciseId, makeMain }`: выбранный на тренировке вариант запоминается в `alternatives` слота (до 6); `makeMain` делает его основным, старое основное — первым аналогом. Оверрайд дня (`WorkoutPlanOverride`) не трогается.
- **Тренировка** — `getActive` отдаёт `mainExerciseId` и `suggestMain` (аналог из двух последних завершённых тренировок этого дня, когда основное в них не делалось). Клиент: `swapSlot` хранит основное слота (`mainExerciseId/mainNameRu/mainSlug`); замена **не удаляет** подходы — они остаются отдельным упражнением тренировки (и для следующих упражнений с частичными подходами); подтверждение «подходы будут сброшены» убрано.
- **Шторка аналогов** (позже перенесена во вкладку, см. §9) — [AlternativesPanel.jsx](../src/pages/Main/workout/AlternativesPanel.jsx): текущее, основное слота (если сегодня другое), аналоги слота, кандидаты каталога; у каждого — последний результат (`batch-last-results`, «…» пока грузится) и статус из сводки; тап — «только сегодня», кнопка «Сделать основным» (только в тренировке по программе). Чип «Аналоги» виден всегда, даже без аналогов в программе.
- **Подсказка** — баннер в активной карточке: «Последние две тренировки ты делал «X». Сделать его основным?» → «Сделать основным» / «Оставить как есть» (скрывается до конца тренировки).
- **Не проверено вживую:** кнопка «Сделать основным», баннер и запоминание в программе из UI (на dev нет тренировки по плану); сервер проверен через API на dev-программе, логика — тестами.

## 9. Реализация фазы 2

- **Экран программы** — [ProgramAlternatives.jsx](../src/pages/Main/program/ProgramAlternatives.jsx) в шторке редактирования упражнения: список аналогов (названия из каталога) с «Сделать основным» и ×; подсказки `GET /exercises/:id/alternatives` (до 5, без уже выбранных); поиск по каталогу от 2 символов. До 6 аналогов. Правки идут в редактируемый план и сохраняются общим `PATCH /programs/:id` (метка `alternativesAuto` при этом снимается — правка ручная). В строке упражнения — «аналогов: N». Мышцы нового основного обновятся после сохранения.
- **Чат-тренер** — инструмент `edit_exercise_alternatives` (`dayIndex`, `exercise`, `addExerciseIds`, `removeExercises`, `makeMainExerciseId`), операция `alternatives` в [programEditor.js](../server/src/services/aiTrainer/programEditor.js), всегда в шаблон программы (для разового оверрайда аналоги не нужны). `get_program_details` отдаёт названия аналогов. Промпт: «добавь вариант / сделай гантели основными» — это аналоги, не замена.
- **`replace_exercise` больше не стирает аналоги:** новое упражнение становится основным, старое — первым аналогом, остальные сохраняются (раньше `alternatives: []`).
- **Аналоги переехали в шторку информации (i).** Чип «Аналоги» в карточке упражнения убран; в `ExerciseDetailSheet` для текущего упражнения тренировки есть вкладка «Аналоги» (проп `alternatives`, на других экранах вкладки нет). Внутри — [AlternativesPanel.jsx](../src/pages/Main/workout/AlternativesPanel.jsx): текущее, основное слота, аналоги слота, кандидаты каталога и **поиск по всей базе** («Любое упражнение из базы»). Выбор закрывает шторку и меняет упражнение на сегодня (и запоминает его в слоте программы).

## 10. Целевая мышца и близкие аналоги

- **Разметка каталога.** У каждого из 928 упражнений (924 из сида + 4 созданных на проде) есть **целевая мышца** — то, на что оно работает в основном, точнее `primaryMuscles`: `upper_chest / mid_chest / lower_chest`, `front_delt / side_delt / rear_delt`, `lats`, `middle back`, `traps`, `lower back`, `biceps`, `triceps`, `forearms`, `quadriceps`, `hamstrings`, `glutes`, `calves`, `adductors`, `abductors`, `abdominals`, `obliques`, `neck` или `none` (растяжки, МФР, кардио, прыжки, олимпийские движения — 236 шт.). Разметка — один прогон LLM ([classifyTargetMuscles.js](../server/scripts/classifyTargetMuscles.js), возобновляемый), результат в [exercise-targets.json](../server/data/exercise-targets.json) по slug; сид переносит его в колонку `Exercise.targetMuscle` (индекс), подбор аналогов фильтрует по ней в SQL. Новое упражнение без разметки → целевая мышца неизвестна (null).
- **Подбор аналогов** ([exerciseAlternatives.js](../server/src/services/exerciseAlternatives.js)): только та же целевая мышца и тот же тип (базовое ↔ базовое, изолирующее ↔ изолирующее). Неизвестна целевая — аналогов нет («лучше не предлагать»). Правило «общее движение в названии» снято: близость теперь задаёт целевая мышца (жим гантелей лёжа получает и отжимания). `fill-alternatives { refreshAuto: true }` перезаполняет все слоты, помеченные как автозаполненные.
- **Уточнение после перезаполнения прода:** внутри целевой мышцы оставляем варианты с тем же движением в названии (слова-снаряды — «штангой», «блоке», «кроссовере»… — не считаются); если таких нет — вся группа. История пользователя влияет только на порядок: то, что он делает выпады, не делает их аналогом жима ногами (цена — у подтягиваний нет тяги верхнего блока). Тип (базовое/изолирующее) сверяется только у упражнений каталога: у созданных позже стоит дефолтный `compound`.
- **API**: `targetMuscle` в `GET /exercises` и `GET /exercises/:id`.
- **Шторка упражнения (i):** вкладки «Инфо · Аналоги · Настройки». «Инфо» = картинка/видео → целевая мышца → «Также работают» (основные мышцы другой группы) → вспомогательные → характеристики → описание, ошибки, видео, техника. Схема тела убрана. В подзаголовке — целевая мышца.
- **Выбор аналога:** тап по варианту открывает его шторку-описание (только «Инфо»); внизу «Выбрать» и, в тренировке по программе, «Выбрать и сделать основным». «Назад» возвращает к списку.
- **Названия упражнений.** Часть русских названий в каталоге была переведена неверно (разводки и сведения на наклонной названы «жимом», `leverage-deadlift` — «Жим ногами в тренажёре», `thigh-abductor` — «Сведение ног», `standing-leg-curl` — «лёжа»…). 26 исправлений — в `enriched-exercises.json` и в [exercise-name-fixes.json](../server/data/exercise-name-fixes.json) (`slug`, `from`, `to`). Применение к существующей базе — [fixExerciseNames.js](../server/scripts/fixExerciseNames.js): dry run по умолчанию, `--apply` пишет одной транзакцией только `nameRu` перечисленных slug и только там, где в базе ещё старое значение. Программы ссылаются на ID — аналоги сразу показывают новые названия; название, скопированное в `planJson` основного упражнения, не меняется.
